## Слайд 3. Два ключевых ограничения платформы

**1. Файловая система в рантайме недоступна.**
Агенты в AI Agents не должны работать с файловой системой во время выполнения. Все необходимые файлы и зависимости нужно упаковывать на этапе сборки Docker-образа.

**2. Переменные окружения прокидываются автоматически.**
AI Agents автоматически передаёт готовые переменные окружения в контейнер — настраивать их вручную не нужно.

> **Пояснение:** Это критически важное ограничение. Вы не можете сделать `open("config.json")` или `os.listdir("/data")` — файловая система только для чтения. Всё, что нужно агенту, должно быть встроено в образ или приходить через env-переменные. Это делает образ самодостаточным и безопасным.

## Слайд 4. Переменные окружения AI Agents

| Переменная | Описание |
|---|---|
| `PHOENIX_ENDPOINT` | Endpoint для просмотра трейсов агента |
| `AGENT_NAME` | Название агента (UI) |
| `AGENT_DESCRIPTION` | Описание агента (UI) |
| `LLM_MODEL` | Модель, например `ollama_chat/llama3.2:3b` |
| `LLM_API_BASE` | `http://localhost:11434/v1 (Ollama)` |
| `LLM_API_KEY` | API-ключ для доступа к Foundation Models |
| `AGENT_SYSTEM_PROMPT` | Системный промпт агента |
| `MCP_URL` | Список URL MCP-серверов через запятую |
| `PORT` | Порт, на котором работает агент |

> **Пояснение:** AI Agents сам подставляет эти переменные. Вам не нужно их настраивать в UI — они уже есть. Но вы должны их **читать** в коде через `os.getenv()`. `MCP_URL` — это список MCP-серверов, которые агент может использовать. Разбивается по запятой.

## Слайд 5. Что такое Google ADK

**ADK (Agent Development Kit)** предоставляет декларативные абстракции:

- **Agent** — имя, описание, инструкция, модель, список инструментов
- **Toolset** — группа инструментов, в том числе подключение к MCP-серверам
- **Session Service** — управление историей диалога
- **Runner** — цикл исполнения задачи агента

> **Пояснение:** ADK — это "конструктор" для агентов. Вы описываете, кто агент (имя, роль), что он умеет (инструменты), и как он должен себя вести (instruction). ADK сам управляет циклом: получает запрос → вызывает LLM → LLM решает, какой инструмент вызвать → агент вызывает инструмент → получает результат → формирует ответ.

---

## Слайд 6. Что такое A2A

**Agent-to-Agent** — протокол взаимодействия между агентами и клиентами.

Агент публикует **AgentCard** (имя, версия, URL, поддерживаемые форматы, список `skills`) и обрабатывает задачи, отдавая результат потоково.

> **Пояснение:** A2A — это как REST API, но для агентов. Вместо "GET /users" вы делаете "отправь задачу агенту". АгентCard — это "документация" агента: кто он, что умеет, как к нему обратиться. Streaming — это "потоковые ответы": агент отправляет чанки по мере генерации, а не ждёт конца и отправляет всё сразу.

## Слайд 7. Декларативное определение агента

```python
from google.adk.agents import Agent
from google.adk.models.lite_llm import LiteLlm
from google.adk.tools.mcp_tool import SseConnectionParams, McpToolset

llm_model = LiteLlm(
    model=os.getenv("LLM_MODEL"),
    api_base=os.getenv("LLM_API_BASE"),
    api_key=os.getenv("LLM_API_KEY"))

worker_agent = Agent(
    model=llm_model,
    name=os.getenv('AGENT_NAME', 'Work Agent').replace(" ", '_'),
    description=os.getenv('AGENT_DESCRIPTION', 'This agent do work'),
    instruction=os.getenv("AGENT_SYSTEM_PROMPT"),
    tools=[McpToolset(
        connection_params=SseConnectionParams(url=url))
        for url in os.getenv("MCP_URL").split(',')],
)

root_agent = worker_agent
```

> **Пояснение:** Весь агент читается из переменных окружения — один образ переиспользуется для разных агентов. `MCP_URL` разбивается по запятой, и для каждого URL создаётся отдельный `McpToolset`. `.replace(" ", '_')` нужен, потому что имя агента должно быть валидным идентификатором (без пробелов).

## Слайд 8. A2A-обёртка и AgentCard

```python
agent_card = AgentCard(
    name=os.getenv('AGENT_NAME', 'Work Agent'),
    description=os.getenv('AGENT_DESCRIPTION', '...'),
    url=os.getenv('URL_AGENT'),
    version=os.getenv('AGENT_VERSION', '1.0.0'),
    default_input_modes=agent_wrapper.SUPPORTED_CONTENT_TYPES,
    default_output_modes=agent_wrapper.SUPPORTED_CONTENT_TYPES,
    capabilities=AgentCapabilities(streaming=True),   # ← включает streaming
    skills=[...],
)

request_handler = DefaultRequestHandler(
    agent_executor=agent_task_manager,
    task_store=InMemoryTaskStore(),
)

server = A2AStarletteApplication(agent_card=agent_card,
                                 http_handler=request_handler)
app = server.build()
app.add_middleware(CORSMiddleware, allow_origins=["*"], ...)

uvicorn.run(app, host='0.0.0.0', port=int(os.getenv("PORT", 10000)))
```

> **Пояснение:** `AgentCapabilities(streaming=True)` — **без этого флага потоковые ответы не передаются**. `CORS` middleware нужен, чтобы к агенту мог обращаться браузер (например, из лаб. 10). `InMemoryTaskStore` хранит историю задач в памяти — при перезапуске контейнера она теряется.


Отправить сообщение через A2A-клиент (или curl к A2A-endpoint), получить ответ и потоковые чанки. Убедиться, что агент читает `MCP_URL` и видит инструменты MCP-сервера.

> **Пояснение:** Для локального запуска нужен ключ LLM. В AI Agents ключ подставляется автоматически через `EVOLUTION_SERVICE_ACCOUNT_KEY_ID` и `EVOLUTION_SERVICE_ACCOUNT_KEY_SECRET`. Если агент не вызывает инструменты — проверьте `MCP_URL` и `AGENT_SYSTEM_PROMPT`: промпт должен явно указывать агенту использовать инструменты MCP.

## Слайд 10. Разбор Dockerfile

**Обратить внимание на:**
- Отсутствие `COPY` файлов данных во время выполнения
- Установка всех зависимостей на этапе сборки
- `CMD`, запускающий A2A-сервер на `0.0.0.0:$PORT`

> **Пояснение:** Dockerfile для агента — это "печать торта": все ингредиенты (зависимости, код) смешиваются на этапе сборки. В рантайме — только готовый торт. Это значит: `pip install` или `uv sync` в Dockerfile, а не в `CMD`. `CMD` — только запуск сервера.

## Слайд 11. Сборка и публикация образа

```bash
docker buildx build --platform linux/amd64 -t adk-agent .
docker tag adk-agent:latest localhost:5000/adk-agent:v1.0.0
```

> **Пояснение:** `--platform linux/amd64` обязателен. `docker tag` переименовывает образ в полный путь с реестром. `docker push` загружает образ в Artifact Registry. После этого AI Agents может его скачать и запустить.

## Слайд 16. Типичные ошибки

| Проблема | Причина | Решение |
|---|---|---|
| Агент не стартует | Не заданы ключи LLM | Проверить `LLM_API_KEY` и `LLM_API_BASE` |
| Ошибка при `MCP_URL` | Переменная пуста, `.split(',')` вернёт пустой список | Задать `MCP_URL` или обработать пустое значение |
| Нет streaming | Не задана `AgentCapabilities(streaming=True)` | Добавить флаг в `AgentCard` |
| Образ не запускается | Собран под неверной платформой | Пересобрать с `--platform linux/amd64` |
| Агент не вызывает инструменты | Нет MCP-сервера или слабый промпт | Выбрать MCP-сервер в UI, усилить инструкции в `AGENT_SYSTEM_PROMPT` |

> **Пояснение:** Самая частая ошибка — "агент не вызывает инструменты". Это может быть по двум причинам: 1) MCP-сервер не выбран в UI, 2) системный промпт слишком слабый. Если промпт говорит "ты полезный ассистент", агент не знает, что он должен использовать инструменты. Нужно явно указать: "используй инструменты MCP-сервера для расчёта кредитов".
