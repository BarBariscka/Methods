## Слайд 3. Что такое MCP-сервер

**MCP-сервер** — сервис, предоставляющий набор **инструментов (tools)** для агента.

**FastMCP берёт на себя:**
- Запуск сервера (транспорт `streamable-http` или `sse`)
- Регистрацию и описание инструментов
- Сериализацию/десериализацию аргументов и результатов
- Автоматическую генерацию спецификаций для клиента
- Поддержку метрик Prometheus и OpenTelemetry

> **Пояснение:** Представьте MCP-сервер как "меню ресторана" для агента. Агент видит список блюд (инструментов) с описанием (docstring), ценами (параметры) и может заказать (вызвать). FastMCP автоматически генерирует это меню из ваших Python-функций.

## Слайд 4. Базовая структура проекта

```
src/
├── mcp_instance.py      # Единый экземпляр FastMCP
├── metrics.py           # Prometheus метрики
```

## Слайд 5. Регистрация инструментов

```python
@mcp.tool
async def loan_schedule_annuity(principal: float,
                                annual_rate_percent: float,
                                months: int,
                                ctx: Context = None) -> dict:
    """Полное и достаточное описание инструмента"""
    if ctx:
        await ctx.info("Начинаем расчет...")
        await ctx.report_progress(progress=0, total=100)
    # валидации и расчёты
    if ctx:
        await ctx.report_progress(progress=100, total=100)
    return {"summary": {...}, "schedule": [...]}
```

> **Пояснение:** FastMCP автоматически создаёт описание инструмента из аннотаций типов и docstring. Type hints (`float`, `int`) превращаются в JSON-схему, а docstring — в описание для агента. `Context` позволяет логировать и отправлять прогресс при длительных операциях.

## Слайд 6. Как правильно писать описания MCP-тулов

1. **Docstring обязателен.** Первые 1–2 строки — краткое назначение, далее формат входа и выхода.
2. **Описание аргументов** в секции `Args:` — тип, допустимый диапазон, смысл.
3. **Описание возвращаемых данных** в `Returns:` — структура словаря и ключи.
4. **Описание исключений** — при каких условиях поднимается `ValueError`.
5. **Примечания** в `Note:` — округления, коррекции, ограничения.

> **Пояснение:** Агент выбирает инструмент **только по описанию**. Если описание плохое — агент вызовет не тот инструмент или передаст неверные параметры. Docstring должен быть самодостаточным: читая только его, агент должен понять, когда и как использовать инструмент.

## Слайд 7. Инструменты сервера

| Инструмент | Назначение |
|---|---|
| `loan_schedule_annuity` | Аннуитетный кредит: фиксированный платёж, график |
| `loan_schedule_differential` | Дифференцированный кредит: убывающий платёж |
| `deposit_schedule_compound` | Вклад с капитализацией и взносами |
| `compare_loan_schedules` | Сравнение аннуитетного и дифференцированного |
| `investment_calculator` | Рост инвестиций с регулярными взносами |

> **Пояснение:** Пять инструментов покрывают базовые финансовые сценарии. Каждый возвращает `summary` (итоговые цифры) и `schedule` (помесячный график). Формулы: аннуитет `M = P·i/(1-(1+i)^(-n))`, дифференцированный — тело `P/n` + проценты на остаток.

---

## Слайд 8. Формула аннуитетного платежа

```
M = P · i / (1 − (1 + i)^(−n))
```

Где:
- `P` — сумма кредита (principal)
- `i` — месячная ставка = годовая / 12
- `n` — срок в месяцах
- `M` — ежемесячный платёж

Для каждого месяца: `payment`, `interest`, `principal_component`, `remaining_principal`, `cumulative_interest`, `cumulative_principal`.

> **Пояснение:** Аннуитетный платёж фиксирован весь срок. В начале большая часть платежа — проценты, к концу — тело кредита. В последний месяц делается **коррекция**: тело = остаток, чтобы `remaining_principal` стал ровно `0.00`. Это важно для совпадения с Python-версией в лаб. 9.

## Слайд 9. Слой валидации

```python
# src/validators.py
def validate_positive_number(name, value, min_inclusive, max_inclusive):
    if not is_finite(value):
        raise ValueError(f"{name}: значение не является конечным числом.")
    if value < min_inclusive:
        raise ValueError(f"{name}: значение должно быть ≥ {min_inclusive}.")
    if value > max_inclusive:
        raise ValueError(f"{name}: значение слишком велико (>{max_inclusive}).")

def check_principal(x: float) -> None:
    validate_positive_number("principal", x, 1e-9, MAX_PRINCIPAL)
```

> **Пояснение:** FastMCP проверяет **типы** по аннотациям (float, int). Но бизнес-ограничения (диапазоны, лимиты, конечность значений) проверяются отдельно. Это даёт агенту понятные сообщения об ошибках: не "type error", а "сумма кредита должна быть ≥ 0.000000001".

## Слайд 10. Метаданные инструмента в декораторе

```python
@mcp.tool(
    name="loan_schedule_annuity",
    description="Аннуитетный кредит: расчёт фиксированного платежа",
    annotations={"title": "График аннуитетного кредита",
                 "readOnlyHint": True,
                 "idempotentHint": True,
                 "openWorldHint": True},
    tags={"credit", "loan", "annuity", "schedule"},
)
async def loan_schedule_annuity(
    principal: float = Field(..., description="Сумма кредита (> 0)"),
    annual_rate_percent: float = Field(..., description="Годовая ставка, %"),
    months: int = Field(..., description="Срок в месяцах"),
    ctx: Context = None,
) -> ToolResult:
    ...
```

> **Пояснение:** `annotations` подсказывают агенту свойства инструмента: `readOnlyHint` — не меняет данные, `idempotentHint` — повторный вызов безопасен, `openWorldHint` — использует внешние данные. `tags` группируют инструменты. `pydantic.Field` с `description` — источник описаний параметров в JSON-схеме.

## Слайд 11. Middleware в server.py

```python
mcp.add_middleware(FriendlyErrorHandlingMiddleware(...))   # понятные ошибки агенту
mcp.add_middleware(RateLimitingMiddleware(
    max_requests_per_second=50.0, burst_capacity=20))     # защита от перегрузки
mcp.add_middleware(TimingMiddleware())                     # тайминги
mcp.add_middleware(LoggingMiddleware(include_payloads=False,
                                     max_payload_length=500))
```

> **Пояснение:** Middleware — это "фильтры" перед каждым вызовом инструмента. `RateLimitingMiddleware` защищает от DDoS (агент может зациклиться и слать 1000 запросов/сек). `FriendlyErrorHandlingMiddleware` превращает технические ошибки в понятные сообщения. `TimingMiddleware` замеряет длительность для метрик.

## Слайд 12. Метрики, трейсинг и коды ошибок

**Метрики Prometheus:**
- `TOOL_CALLS` — счётчик вызовов инструментов
- `CALCULATION_ERRORS` — ошибки расчётов
- `API_CALLS` — вызовы API

**OpenTelemetry:**
- `tracer.start_as_current_span(tool_name)` — спан вокруг расчёта

**Коды ошибок MCP:**
- `ValueError` → `McpError(ErrorData(code=-32602))` — неверные параметры
- Прочие исключения → `McpError(ErrorData(code=-32603))` — внутренняя ошибка

> **Пояснение:** Код `-32602` (Invalid params) говорит агенту: "измени параметры и попробуй снова". Код `-32603` (Internal error) — "сервер упал, попробуй позже или сообщи админу". Это разные стратегии обработки для агента.

## Слайд 15. Сборка Docker-образа

```bash
docker buildx build --platform linux/amd64 -t mcp-finance .
docker run --rm -p 8000:8000 -e PORT=8000 mcp-finance
```

> ⚠️ **Важно:** MCP-сервер в AI Agents **не должен использовать файловую систему в рантайме** — все манипуляции выполняются на этапе сборки образа.

> **Пояснение:** `--platform linux/amd64` обязателен, потому что AI Agents работают на Linux-серверах. Если собрать образ под Windows или ARM, он не запустится. "Без файловой системы в рантайме" означает: нельзя писать логи в файлы, читать конфиги с диска — всё должно быть в памяти или приходить через env-переменные.

## Слайд 20. Типичные ошибки

| Проблема | Причина | Решение |
|---|---|---|
| Port 8000 занят | Другой процесс слушает порт | Задать другой `PORT` в `.env` |
| `ModuleNotFoundError` | Не настроен путь импорта | `PYTHONPATH=src` или `uv sync` |
| Агент не видит инструменты | MCP-сервер не выбран в UI | Выбрать MCP-сервер в настройках агента |
| Неверные расчёты | Не учтено округление | Округлять до 2 знаков; в последний месяц — коррекция |
| Ошибка при импорте метрик | Не установлен `prometheus_client` | `uv sync` |

> **Пояснение:** Самая частая ошибка — "агент не видит инструменты". Это значит, что в UI AI Agents при создании агента не выбран MCP-сервер. Вторая по частоте — неверные расчёты из-за округления: деньги всегда округляются до 2 знаков, а в последний месяц делается коррекция, чтобы остаток стал ровно 0.00.

## Слайд 20. Контрольные вопросы

1. Что такое MCP и зачем он нужен AI-агентам? Какова связь MCP и протокола A2A?
2. Как FastMCP превращает Python-функцию в инструмент? Какую роль играют type hints и docstring?
3. Чем аннуитетный платёж отличается от дифференцированного? Приведите формулы.
4. Зачем нужен отдельный слой валидации, если FastMCP уже проверяет типы?
5. Какую роль играют middleware (rate limiting, timing, logging) и как они подключаются?

> **Пояснение:** Вопросы проверяют понимание архитектуры. MCP — это "меню инструментов" для агента, A2A — протокол общения агентов между собой. FastMCP использует type hints для JSON-схемы, docstring — для описания. Валидация нужна для бизнес-правил (лимиты), которые нельзя выразить типами. Middleware — это AOP (аспектно-ориентированное программирование) для кросс-сечных задач.
