## Слайд 3. Code Agent против Tool Calling Agent

| | Tool Calling Agent | Code Agent |
|---|---|---|
| Как действует | Выбирает готовый инструмент и передаёт аргументы | Пишет фрагмент Python-кода и исполняет его |
| Шаги на задачу | Много (цикл «рассуждение → вызов → ответ») | Мало (один блок кода решает составную задачу) |
| Гибкость | Ограничена набором инструментов | Практически любая вычислительная задача |
| Расход токенов | Выше | Ниже |

> **Пояснение:** Tool Calling — это «менеджер, который раздаёт задания специалистам». Code Agent — это «специалист, который сам пишет себе инструкцию». Для составных вычислительных задач второй эффективнее: один фрагмент кода заменяет несколько циклов вызова инструментов.

## Слайд 4. Почему меньше вызовов LLM

Code Agent объединяет несколько вызовов инструментов в один фрагмент кода вместо цикла «рассуждение → один tool call → ответ» на каждом шаге.

**Результат:** сокращение числа шагов и вызовов LLM примерно на **30%** — это видно в трейсах Phoenix.

> **Пояснение:** Это ключевая метрика для сравнения с лаб. 3. В самостоятельной части мы включаем Phoenix на обоих агентах, выполняем одинаковую задачу и сравниваем число шагов, вызовов LLM и время выполнения.

## Слайд 5. Меры безопасности

- **Sandboxed execution** — выполнение кода в изолированной среде (например, E2B).
- **`max_iterations`** — жёсткий лимит длины цикла агента.
- **Изоляция контейнера** — в AI Agents агент работает в отдельном окружении без доступа к файловой системе хоста.

> **Пояснение:** Code Agent исполняет код, сгенерированный моделью, — это потенциально опасно. Поэтому обязательны три уровня защиты: песочница для исполнения, лимит итераций против зацикливания и изоляция контейнера.

## Слайд 6. ⚠️ Замечание для Intel Mac

SmolAgents имеет транзитивную зависимость от `torch`, который **не поддерживает Intel Mac (x86_64) с macOS 14+**. На этой платформе `uv sync` может завершиться ошибкой.

**Решение:** использовать Docker для разработки и развёртывания — Docker-образ работает на Linux, где `torch` поддерживается полностью.

> **Пояснение:** Это частая «ловушка» на этапе подготовки. Если у вас Intel Mac — не тратьте время на отладку `uv sync`, сразу переходите в Docker. На Windows/Linux и Apple Silicon проблем нет.

## Слайд 7. Определение CodeAgent

```python
# src/agent.py
from smolagents import CodeAgent, Tool
from litellm import completion

def create_smolagents_agent(mcp_urls=None):
    def llm_call(messages, **kwargs):
        """Обертка для вызова LLM через LiteLLM."""
        response = completion(
            model=os.getenv("LLM_MODEL", "gpt-4"),
            messages=messages,
            api_base=os.getenv("LLM_API_BASE"),
            api_key=os.getenv("LLM_API_KEY"),
            **kwargs)
        return response.choices[0].message.content

    tools = get_mcp_tools(mcp_urls)
    system_prompt = os.getenv("AGENT_SYSTEM_PROMPT",
        "Ты полезный AI-ассистент. Используй доступные инструменты "
        "для решения задач пользователя.")

    agent = CodeAgent(tools=tools, llm=llm_call,
                      system_prompt=system_prompt,
                      max_iterations=15)
    return agent
```

> **Пояснение:** `llm_call` — единая точка подключения к LLM через LiteLLM. `max_iterations=15` ограничивает длину цикла и защищает от зацикливания и бесконечного расхода токенов. Для локального запуска с LiteLLM модель задаётся **с** префиксом: `ollama_chat/llama3.2:3b`.

## Слайд 8. Адаптация MCP-инструмента

```python
def create_mcp_tool(mcp_url: str, tool_name: str,
                    tool_description: str) -> Tool:
    def mcp_tool_func(input_text: str) -> str:
        async def async_call():
            async with httpx.AsyncClient(timeout=30.0) as client:
                response = await client.post(
                    f"{mcp_url}/tools/{tool_name}/invoke",
                    json={"input": input_text},
                    headers={"Content-Type": "application/json"})
                response.raise_for_status()
                result = response.json()
                return str(result.get("content", result))
        return asyncio.run(async_call())

    return Tool(name=tool_name,
                description=tool_description,
                function=mcp_tool_func)
```

> **Пояснение:** Разница с LangChain (лаб. 3): объект `Tool` создаётся с полем `function=`, а не `func=`. Это частая причина ошибок при переносе кода между фреймворками. Описание инструмента (`description`) критично — по нему LLM решает, какой инструмент вызвать.

## Слайд 9. A2A-обёртка

`SmolAgentsA2AWrapper` преобразует интерфейс SmolAgents-агента в A2A-совместимый формат:

- поддержка streaming через `run_stream` (если доступен);
- управление сессиями и историей диалога;
- обработка ошибок.

> **Пояснение:** A2A-обёртка не зависит от фреймворка агента — она одинакова для ADK, LangChain, Strands и CrewAI. Меняется только определение агента внутри. `AgentCapabilities(streaming=True)` — без этого флага потоковые ответы не передаются.

## Слайд 13. Отличия от других фреймворков

1. **Простота** — минимальный API и зависимости.
2. **Code Agents** — агент пишет и выполняет Python-код.
3. **Эффективность** — уменьшает количество шагов и вызовов LLM на ~30%.
4. **Безопасность** — поддержка sandboxed execution (E2B).

> **Пояснение:** SmolAgents выигрывает там, где задачи вычислительные и составные. Проигрывает там, где нужна строгая маршрутизация между многими разнородными инструментами — там удобнее LangChain/CrewAI.

## Слайд 14. Самостоятельное задание

Добавить агенту **собственный tool** — Python-функцию с декоратором `@tool`, например конвертер валют с фиксированными курсами:

```python
from smolagents import tool

@tool
def currency_converter(amount: float, rate: float) -> str:
    """Конвертирует сумму по фиксированному курсу.

    Args:
        amount (float): исходная сумма.
        rate (float): курс перевода.
    """
    return f"{amount * rate:.2f}"
```

Добавить инструмент в `tools`, передать в `CodeAgent(tools=[...])` и проверить вызов по запросу «переведи 100 долларов в рубли по курсу 95».

> **Пояснение:** Декоратор `@tool` превращает обычную Python-функцию в инструмент: имя функции становится именем инструмента, а docstring — его описанием (по нему LLM решает, когда вызывать).

## Слайд 18. Типичные ошибки

| Проблема | Причина | Решение |
|---|---|---|
| `uv sync` падает на Intel Mac | `torch` не поддерживает x86_64 macOS 14+ | Работать в Docker |
| Ошибки выполнения кода | Промпт не разрешает выполнение кода, нет изоляции | Проверить системный промпт, использовать sandbox |
| Модель не найдена | Нет префикса `ollama_chat/` для litellm | Добавить префикс к `LLM_MODEL` |
| Агент зациклился | Слишком сложная задача | Уменьшить `max_iterations`, разбить задачу |
| `Tool` не принимается | Передано поле `func` вместо `function` | Использовать `function=mcp_tool_func` |

> **Пояснение:** Две самые частые ошибки — формат имени модели (префикс `ollama_chat/`) и поле `function` вместо `func` при создании инструмента. Обе легко ловятся по сообщению об ошибке.
