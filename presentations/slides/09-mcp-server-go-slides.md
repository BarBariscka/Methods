## Слайд 3. MCP без фреймворка

**В Python используется FastMCP**, который берёт на себя запуск сервера, маршрутизацию и сериализацию.

**В Go такого фреймворка нет** — протокол реализуется вручную поверх HTTP:

1. HTTP-обработчик endpoint `/mcp`
2. Разбор тела запроса как JSON-RPC: `{"jsonrpc": "2.0", "id": 1, "method": "...", "params": {...}}`
3. Диспетчер по `method`: `initialize`, `tools/list`, `tools/call`
4. Извлечение параметров и вызов обработчика инструмента
5. Формирование JSON-RPC-ответа

> **Пояснение:** FastMCP в Python — это "магический" фреймворк, который автоматически генерирует спецификации из type hints и docstring. В Go всё нужно делать вручную: парсить JSON-RPC, извлекать параметры, вызывать функции, формировать ответы.

## Слайд 4. Что даёт статическая типизация

| Аспект | Python (FastMCP) | Go |
|---|---|---|
| Схема инструмента | Строится из type hints + docstring в рантайме | Структуры `ScheduleEntry`, `LoanSummary`, `CalculationResult` — ошибки компиляции |
| Извлечение параметров | `Field` + автоматическая валидация | Ручное извлечение с проверкой типа: `params["principal"].(float64)` |
| Возврат ошибок | `ValueError`, `McpError` | `(interface{}, error)` |
| Скомпилированный бинарник | Нет | Да — один файл, быстрый старт |

> **Пояснение:** Статическая типизация в Go означает, что ошибки ловятся на этапе компиляции, а не в рантайме. Если вы передадите `string` вместо `float64`, компилятор скажет об этом сразу. В Python ошибка возникнет только при вызове функции.

## Слайд 5. Плюсы и минусы Go-подхода

**Плюсы:**
- Статическая типизация
- Высокая производительность
- Один статический бинарник без зависимостей
- Встроенный `go test`, отличная стандартная библиотека
- Удобная конкурентность

**Минусы:**
- Ручная реализация протокола (больше кода)
- Нет готовых декораторов
- Спецификации инструментов приходится описывать отдельно
- Кривая обучения для тех, кто пришёл из Python

> **Пояснение:** Go — это "ручной" подход. Вы пишете больше кода, но получаете больше контроля. Python — это "быстрый" подход. Вы пишете меньше кода, но теряете контроль.

## Слайд 10. Обработчик инструмента

```go
type ToolHandler func(ctx context.Context,
    params map[string]interface{}) (interface{}, error)

func LoanScheduleAnnuityHandler(cfg *config.Config,
    tracer trace.Tracer) ToolHandler {
    return func(ctx context.Context,
        params map[string]interface{}) (interface{}, error) {
        toolName := "loan_schedule_annuity"

        ctx, span := tracer.Start(ctx, toolName)
        defer span.End()

        principal, ok := params["principal"].(float64)
        if !ok {
            return nil, fmt.Errorf("invalid parameter: principal")
        }
        annualRatePercent, ok := params["annual_rate_percent"].(float64)
        if !ok {
            return nil, fmt.Errorf("invalid parameter: annual_rate_percent")
        }
        monthsFloat, ok := params["months"].(float64)
        if !ok {
            return nil, fmt.Errorf("invalid parameter: months")
        }
        months := int(monthsFloat)

        // ... валидация и расчёт
        result, err := calculations.AnnuitySchedule(principal, annualRatePercent, months)
        if err != nil {
            return nil, err
        }

        return result, nil
    }
}
```

> **Пояснение:** **Важно:** JSON числа всегда приходят как `float64` — даже целые. Поэтому `months` извлекается как `float64`, а затем приводится к `int`. Это частая ошибка новичков.

## Слайд 11. Алгоритм аннуитетного кредита

```go
func AnnuitySchedule(principal, annualRatePercent float64,
                     months int) (*CalculationResult, error) {
    P := principal
    n := months
    r := annualRatePercent / 100.0 / 12.0

    var monthlyPayment float64
    if r == 0.0 {
        monthlyPayment = P / float64(n)   // нулевая ставка
    } else {
        monthlyPayment = P * r / (1.0 - math.Pow(1.0+r, float64(-n)))
    }

    for m := 1; m <= n; m++ {
        interest := remaining * r
        principalComponent := monthlyPayment - interest

        if m == n {
            // коррекция последнего платежа
            principalComponent = remaining
            monthly = principalComponent + interest
        } else {
            monthly = monthlyPayment
        }

        // округление до 2 знаков
        remaining = utils.Round2(remaining - principalComponent)
        schedule = append(schedule, ScheduleEntry{...})
    }

    return &CalculationResult{Summary: summary, Schedule: schedule}, nil
}
```

> **Пояснение:** Две особенности, обеспечивающие совпадение с Python-версией: 1) **Коррекция последнего платежа** — в последнем месяце тело равно остатку, чтобы `remaining_principal` стал ровно `0.00`. 2) **Округление до 2 знаков** (`utils.Round2`) на каждом шаге — иначе на длинных сроках накапливается расхождение с Python.

## Слайд 12. Метрики Prometheus

- `tool_calls_total` — количество вызовов инструментов, лейблы `tool_name`, `status`
- `calculation_errors_total` — ошибки расчётов, лейблы `tool_name`, `error_type`
- `api_calls_total` — вызовы API, лейблы `service`, `endpoint`, `status`

> **Пояснение:** Prometheus — это система мониторинга. Метрики — это "числа", которые мы собираем: сколько раз был вызван инструмент, сколько было ошибок, сколько времени занял расчёт. Лейблы — это "метки", которые помогают фильтровать метрики.

## Слайд 18. Сравнительная таблица Python vs Go

| Критерий | Python (FastMCP) | Go (без фреймворка) |
|---|---|---|
| Объём кода | Меньше: декораторы и генерация схем | Больше: ручная маршрутизация и сериализация |
| Типобезопасность | Типы проверяются в рантайме | Ошибки ловятся компилятором |
| Зависимости | Много (FastMCP, pydantic, prometheus…) | Мало (стандартная библиотека + prometheus) |
| Дистрибуция | Нужен интерпретатор и venv | Один статический бинарник |
| Производительность | Ограничена GIL | Высокая, встроенная конкурентность |
| Тесты | pytest | `go test`, табличные тесты из коробки |
| Ошибки | Исключения (`ValueError`, `McpError`) | Возвращаемые значения `(T, error)` |
| Скорость разработки | Выше для прототипов | Ниже, но надёжнее в проде |

> **Пояснение:** Python — это "быстрый" подход для прототипов. Go — это "надёжный" подход для продакшена. Python быстрее разрабатывать, но Go надёжнее и производительнее.

## Слайд 20. Типичные ошибки

| Проблема | Причина | Решение |
|---|---|---|
| Точка входа отсутствует | Файл `cmd/server/main.go` не был в репозитории | Написать транспорт MCP самостоятельно |
| Неверный тип параметра | JSON-числа приходят как `float64` | Извлекать `float64`, приводить `int(monthsFloat)` |
| Ошибки компиляции | Неверные импорты или версия Go | `go version` (≥ 1.21), `go mod tidy` |
| Ошибки валидации | Не совпадают лимиты | Сверить значения с `env_options.json` |
| Расхождение с Python | Разная стратегия округления | Округлять до 2 знаков на каждом шаге, корректировать последний платёж |
| Отрицательный остаток | Численная ошибка расчёта | Проверка `remaining < -0.01` возвращает ошибку |

> **Пояснение:** Самая частая ошибка — "неверный тип параметра". JSON числа всегда приходят как `float64` — даже целые. Поэтому `months` извлекается как `float64`, а затем приводится к `int`. Вторая по частоте — "расхождение с Python" — это значит, что округление сделано неправильно.
